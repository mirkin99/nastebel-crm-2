# Коммуникации Nastibel — версия для согласования

## Запуск
Открыть `index.html` в браузере. Без подключения работает локальный просмотр (localStorage), без внешних библиотек и ИИ API. Скачиваемый персональный вариант дополнен двумя подтверждёнными записями обхода 08.10.2026. В публичный GitHub контактные данные не включены.

Кнопка «Подключить Supabase» включает общую базу. Пароль тот же, что у существующей CRM. Разделённые режимы не переносят локальные тестовые изменения в облако автоматически. «Экспорт» выдаёт JSON, совместимый с импортом отчётов. Локальные данные не являются резервной копией облака.

## Архитектура
`HTML (UI + проверяемый JSON-импорт)` → `nastebel-communications-api (проверка существующей CRM-сессии)` → `comm_companies (PostgreSQL)`.

Одна карточка = компания в определённой локации. Карточка — атомарный агрегат: поля компании, несколько контактов, история взаимодействий, задачи. В `comm_companies` хранится JSON-документ, UUID, revision, created_at, updated_at и уникальный нормализованный ключ название + локация. Контакты не создают отдельную карточку. Новые филиалы можно вести отдельными карточками. Если название или локация отличаются, автоматическое угадывание соответствия не выполняется: исправить/дополнить существующую карточку вручную.

Дочерние события и задачи имеют UUID. Смена статуса и выполнение задачи добавляют запись истории. Редактирование истории разрешено, поэтому это рабочий журнал, а не неизменяемый аудит.

Этапы: first / Первичный обход → talk / Переговоры → test / Тестовая поставка → active / Сотрудничество; lost / Неактуально требует причину. Разрешён переход в любой этап: не каждый заказ требует теста. Возврат из lost очищает текущую причину; старая остаётся в истории. Статус не создаёт поставку, заказ или оплату.

`client_id` — необязательная явная связь с существующим клиентом складской CRM. Список клиентов доступен после облачного входа. Это не автоматическая регистрация клиента и не изменение финансов. На согласовании кнопка перехода на действующем сайте не добавлена.

## Защита и целостность
- Новый API не изменяет существующую Edge Function или пароль.
- На каждом запросе сервер хеширует случайный CRM-токен и проверяет `crm_sessions` и срок действия. Supabase JWT gateway выключен осознанно: применяется существующая собственная сессия CRM.
- service_role существует только в серверных переменных Supabase. В HTML нет ключей БД, пароля и хеша пароля.
- RLS включён; anon/authenticated/PUBLIC лишены доступа к таблице и функции. Прямой публичный REST доступ отсутствует. service_role используется только после проверки сессии.
- Все пользователи с действительным паролем существующей CRM имеют доступ к модулю. Индивидуальных ролей в существующем входе нет.
- Запись пакета через comm_save_batch выполняется транзакционно. Ошибка одного элемента отменяет весь пакет.
- Изменение и удаление сверяют revision. При конфликте данные не перезаписываются; требуется «Обновить» и повторное редактирование.
- Удаление компании удаляет её контакты, историю и задачи. Учётные клиенты, заказы, оплаты, остатки не затрагиваются.
- JSON отображается через экранирование текста. Телефон преобразуется в tel, wa.me, t.me; Telegram username предпочтительнее ссылки по номеру. Номер 8XXXXXXXXXX нормализуется в 7XXXXXXXXXX. Telegram/WhatsApp не гарантируют наличие аккаунта.

## Импорт без нейросети внутри CRM
Кнопка «Вставить отчёт» содержит полный шаблон. Нейросеть должна выдать `{version:1, companies:[...]}`. Поддерживаются `name`, `location`, `sector`, `notes`, `contacts`, `status`, `reason`, `interaction`, `next_action`; экспорт также содержит `events` и `tasks`.

Сначала пользователь нажимает «Проверить», видит список создаваемых/дополняемых карточек и контакты, затем сохраняет пакет. Подтверждённое совпадение — нормализованные название и локация. Повторное событие определяется датой, типом и текстом, задача — текстом и датой. Повторный отчёт без изменений не сохраняется. Неизвестный статус не выдумывается: новая карточка получает first, существующая сохраняет статус. Дата следующего действия без указания остаётся пустой. Импорт не удаляет отсутствующие данные; для исправления и удаления есть ручное редактирование.

## Файлы
- index.html — автономный интерфейс, без персональных данных в репозитории.
- schema.sql — точный применённый DDL нового модуля; не запускать повторно на той же базе.
- server/index.ts, server/deno.json — исходники отдельной Edge Function, supabase-js 2.95.0.
